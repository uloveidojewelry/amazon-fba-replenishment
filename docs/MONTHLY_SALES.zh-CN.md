# 按用户月销量整理美国站补货

本报表以用户上传的单个 Seller SKU 月销量作为需求基准，已采集的美国站
7/30/60/90 天销量作为对照，不修改原 API 销量记录。美国站识别码为
`ATVPDKIKX0DER`，不合并加拿大站；同名 SKU 的月销量来源站点仍须用户确认。
继续按 SKU 独立计算，原系列映射、系列停补和审核数据保留。

上传 Excel 的前两列分别为 SKU、月销量，第一列标题为 `sku` 或 `SKU`。
精确匹配 Seller SKU，保留大小写、标点及完整名称，不按前缀或系列猜测。
数量必须是非负整数；相同 SKU 相同数量的重复行只计一次并留审计，
数量冲突、空数量、公式及非法数量保留为异常，不求和、不当作零。

未给出实际月份时，月销量除以标准 30 天，并标为 `ASSUMED_30_DAY_MONTH`。
未确认美国站、件数口径、月期间或计算参数时均为 `SCENARIO_ONLY`，
不得作为正式采购依据。API 原始窗口保留各自的日期、完整性及数据来源；
月销量不会替换或伪造 API 近 30 天销量。

默认试算参数：运输入仓 35 天、到货后覆盖 75 天、安全库存 0 天、MOQ/箱规 1。
总需求周期为 110 天，公式为：

```
月销日均 = 用户月销量 / 月销折算天数
原始需求 = max(0, ceil(月销日均 × (运输 + 目标覆盖 + 安全库存)
                       - FBA可售 - 经核对可抵扣在途))
建议件数 = 对正数原始需求按 MOQ 和箱规向上取整
```

预留与不可售库存仅展示；入仓库存摘要与货件余额核对，不与可抵扣在途重复相加。
沿用 `confirmed_eta` 时，只有人工确认到货期限内的在途才抵扣。
未知 ETA、发运/接收冲突、库存缺失、未知 SKU、未完成订单及其他原 API
安全拦截继续使建议留空。已明确生效的 SKU 停补始终为零，不自动恢复。

7 天与 90 天销量另外折合标准 30 天用于对比，用户月销量也按实际天数归一到
标准 30 天后比较。差异达到两倍的提示仅用于人工筛选，不自动加权或改写需求。
API 30 天为零时比值留空并提示，不能以零作除数。月销量表外但有销量、库存、
在途或数据异常的 SKU 单列为待检查，不擅自推断其月销量为零。

离线复算示例（不会认证或请求 Amazon）：

```bash
fba-plan --db output/monthly-sales-20261015/sku_plan.db monthly-plan 用户月销量.xlsx \
  --asof 2026-10-13 --monthly-days 30 \
  --lead-days 35 --target-days 75 --safety-days 0 \
  --output output/monthly-sales-20261015/monthly_replenishment.xlsx
```

仅在用户明确确认全部口径及参数后，才同时使用
`--monthly-scope-confirmed --monthly-period-status USER_CONFIRMED_PERIOD --parameters-confirmed`。
确认参数仍不授权采购或 Amazon 写入。库存刷新通过既有只读采集模块执行；
历史订单快照用于对照时明确标出截止日，不冒充本次重新采集。

Excel 包含补货清单、销量对比、FBA 库存、在途原始发运/接收量与未知余额、
缺货风险、异常、已停补 SKU、月销表外风险、参数、来源审计及汇总。
全部库存采集时间按北京时间显示。数据与密钥均不写入公开代码；
下载使用密码保护副本时只公开密文，密码通过用户对话单独提供。
